# ML_user-churn-prediction
# Прогнозирование оттока клиентов телеком оператора (Telco Customer Churn)

Реализация ML модели для предсказания оттока пользователей оператора связи на основе исторических данных IBM с платформы Kaggle (https://www.kaggle.com/datasets/blastchar/telco-customer-churn)

##  1. Бизнес-контекст и задача
Высокая конкуренция на рынке телекоммуникационных услуг приводит к постоянной миграции пользователей между операторами. Стоимость удержания текущего клиента (Retention Cost) значительно ниже стоимости привлечения нового (CAC). 

Бизнес-цель: создать ML модель, выявляющую пользователей с высоким риском ухода, для последующего проведения таргетированных маркетинговых кампаний (специальные тарифы, скидки, бонусы).
Критерий успеха: повышение метрики Recall при фиксированном уровне Precision (более 70%), чтобы минимизировать пропуск «уходящих» клиентов без чрезмерных затрат на удержание нелояльной аудитории.

## 2. Анализ данных и ключевые инсайты (EDA)
Исходный датасет содержит информацию о 7043 клиентах и 21 признаках таких как:

- Клиенты, которые ушли в течение последнего месяца
- Услуги, на которые подписан каждый клиент 
- Информация об учетной записи клиента 
- Соц-демографическая информация о клиентах 

В данных много зависимостей, в первую очередь это связано с особенностями предоставляемых услуг: если у клиента нет телефона, то в следующем вопросе про несколько линий (MultipleLines) автоматически проставляется ответ "No phone service". Такая же ситуация если у клиента не подключен интернет, ему невозможно предоставить доп. услуги, в этих признаках(фичах) также проставлены "No internet service". Т.е при кодировке категориальных переменных через One-Hot Encoding нужно прописать четкие правила удаления колонок, а не удалять дефолтные первые колонки.

В числовых переменных найдена зависимость общих расходов (TotalCharges), которые представляют собой произведение продолжительности сотрудничества  (tenure) и ежемесячных платежей (MonthlyCharges)

Из графика распределения ежемесячных платежей (MonthlyCharges) видно, что платежи имеют несколько "горбов" как в оттоке, так и у оставшихся. Такое распределение данных сложно для линейных моделей, они отделяют данные плоскостью, а тут явно есть три тарифа эконом, стандарт и премиум. Линейная модель не сможет их корректно разделить. 

Ключевые инсайты EDA:

С большей вероятностью уйдут - новые клиенты (маленький tenure), которые подключили дорогие тарифы или дополнительные услуги (высокий MonthlyCharges).

Отток не зависит от пола, наличия телефона или нескольких линий. 

Вероятность оттока выше у тех, у кого оптоволоконное подключение, нет антивируса, тех поддержки, короткий контракт на месяц и оплата электронными чеками.

 
## 3. Результаты и метрики
В линейных моделях были реализованы LogisticRegression (Lasso, Ridge и elastic-net) и LinearSVC. Так как метрики качества и ранжирование признаков по абсолютной величине коэффициентов оказались схожими, в качестве базовой модели (Baseline) использовалась логистическая регрессия Lasso, метрики которой были:

ROC-AUC: 0.84

Precision равно: 0.70

Recall равно: 0.43

F-мера равно: 0.53


Для улучшения результатов планируется протестировать ансамбли деревьев решений и градиентный бустинг.



 ## 4. Анализ важности признаков (Feature Importance)
Три признака с огромным отрывом определяют качество прогноза. Без них модель полностью потеряет предсказательную силу:
1. MonthlyCharges (Ежемесячный платеж): Самый важный признак для модели. Стоимость услуг имеет решающее значение для клиентов.
2. tenure (Время жизни клиента): На втором месте по важности. Длительность отношений клиента с компанией критически важна для понимания лояльности.
3. Contract (Тип контракта): Замыкает тройку лидеров. Наличие долгосрочного договора - ключевой фактор, удерживающий людей.

Признаки средней важности. Эти факторы вносят стабильный, хотя и меньший вклад в предсказание оттока:
1. Сервисы безопасности и поддержки (OnlineSecurity, TechSupport) - наличие этих опций «привязывает» клиента.
2. Базовые и технические параметры (PhoneService, PaymentMethod, PaperlessBilling): Способ оплаты и наличие телефона важны для модели, их перемешивание заметно снижает метрики.

 ## 5. Интерпретация модели (Инсайты для бизнеса)
Идеальный кандидат на уход выглядит так: «Новый клиент с высоким ежемесячным платежом (MonthlyCharges), без долгосрочного контракта (Month-to-month), который платит электронными чеками вручную и не пользуется техподдержкой».
Для удержания таких клиентов бизнесу нужно:

1. Переводить клиентов на годовые контракты: Давать скидки и бонусы за подписание контракта на 1-2 года, так как это сильнее всего снижает отток.
2. Продавать экосистему (Cross-sell): Активно предлагать пакеты с техподдержкой (TechSupport) и безопасностью (OnlineSecurity).
3. Работать с ценностью, а не только с ценой: Так как MonthlyCharges - главный драйвер ухода, нужно либо предлагать более дешевые тарифы тем, кто собирается уйти, либо наглядно обосновывать ценность дорогого тарифа.
4. Стимулировать автоплатежи: Переводить людей с электронных чеков на автоматическое списание по картам (Credit card имеет отрицательный вес -0.08, что удерживает клиентов).
